# DESIGN: แนวทางการออกแบบหน้าเว็บ

ทิศทางมาจากดีไซน์ Figma เดิม (กรมท่า + ทอง, หัวข้อฟอนต์ไทยแบบมีหัว) และปรับตามข้อสังเกตจากการรีวิว
**ทุกหน้าต้องใช้ token และ component ในไฟล์นี้เท่านั้น** ถ้าต้องการ component ใหม่ ให้เพิ่มในไฟล์นี้และใน `page_styleguide.html` ก่อน แล้วค่อยนำไปใช้

## 1. หลักการ

1. **มือถือก่อน (mobile-first):** ออกแบบที่ 375px ก่อน แล้วขยายที่ `md` (768px) และ `lg` (1024px)
2. **อ่านภาษาไทยสบาย:** เนื้อหาไม่ต่ำกว่า 16px, line-height 1.7, ไม่ใช้ตัวอักษรเล็กกว่า 14px ยกเว้นป้ายกำกับสั้นๆ (13px)
3. **งานหลักต้องเห็นชัด:** ปุ่มหลัก (สีทอง) มีได้ 1 ปุ่มต่อหนึ่งส่วนของหน้า
4. **ภาษาไทยเป็นหลัก:** ป้าย หัวข้อ ปุ่ม เป็นภาษาไทย ไม่ใช้ป้ายภาษาอังกฤษตัวพิมพ์ใหญ่ประดับ (เช่น "NEWS & ANNOUNCEMENTS")
5. **บอกสถานะเสมอ:** ทุกการกระทำต้องมี feedback (กำลังโหลด, สำเร็จ, ผิดพลาด) และทุกรายการต้องมีหน้าว่าง (empty state)
6. **เข้าถึงได้:** สีตัดกันผ่าน WCAG AA (ข้อความปกติ 4.5:1), ทุก input มี `<label>`, focus มองเห็นได้, ใช้งานด้วยคีย์บอร์ดได้

| ใช้ทำอะไร | token |
|---|---|
| พื้นหลัง header ด้านบน, hero, footer | `navy-800` |
| ข้อความบนพื้นกรมท่า | ขาว / `navy-100` (ห้ามใช้เทาจาง) |
| ปุ่มหลัก | พื้น `gold-500` + ตัวอักษร `navy-900` |
| ลิงก์, ปุ่มรอง, ไอคอน | `navy-500` |
| ป้ายกำกับสีทองบนพื้นขาว | `gold-700` (ห้ามใช้ `gold-500` บนพื้นขาว เพราะตัดกันไม่พอ) |
| ข้อความหลัก / รอง / คำอธิบาย | `ink` / `ink-muted` / `ink-subtle` (`ink-subtle` ใช้บนพื้นขาวเท่านั้น บน `surface-alt` ได้ 4.41:1 ไม่ผ่าน ให้ใช้ `ink-muted` แทน) |
| เส้นขอบการ์ด | `line` (เป็นแค่ตกแต่ง) |
| ขอบช่องฟอร์ม, checkbox, dropzone | `ink-subtle` (ขอบของสิ่งที่กดหรือกรอกได้ต้องตัดกัน 3:1 ขึ้นไป `line` ได้แค่ 1.24:1) |
| พื้นส่วนสลับ | `surface-alt` |

### Typography

| ระดับ | class |
|---|---|
| H1 (hero) | `font-heading text-3xl md:text-5xl font-bold leading-tight` |
| H2 (หัวข้อส่วน) | `font-heading text-2xl md:text-3xl font-bold` |
| H3 (หัวการ์ด) | `font-sans text-lg font-semibold` |
| เนื้อหา | `text-base leading-[1.7]` |
| คำอธิบาย / เมตาดาต้า | `text-sm text-ink-muted` (14px) |
| ป้ายกำกับ | `text-[13px] font-medium` |

หัวข้อยาวให้ใช้ `text-wrap: balance` เพื่อไม่ให้เหลือคำเดียวในบรรทัดสุดท้าย (เช่นคำว่า "ไทย" ในดีไซน์เดิม)

### Spacing และ layout

- กรอบเนื้อหา: `mx-auto max-w-content px-4 md:px-6` **ทุกส่วนของหน้า** รวม header และ footer
- ระยะห่างระหว่างส่วน: `py-12 md:py-20`
- grid การ์ด: `grid gap-4 sm:grid-cols-2 lg:grid-cols-3` (หรือ `lg:grid-cols-4` สำหรับการ์ดทางลัด)
- พื้นที่กดบนมือถือไม่เล็กกว่า 44×44px

## 3. Component

ทุก component ต้องมีอยู่ใน `page_styleguide.html` และเขียนเป็น class/ฟังก์ชันกลางใน `css_main.html` / `js_ui.html`
ฟังก์ชันใน `js_ui.html`: `render*()` คืน HTML string ที่ escape แล้ว / `create*()` คืน element ที่มีพฤติกรรมในตัว

## 6. โครงแต่ละหน้า

### หน้าหลัก (`home`)
1. **Hero (navy-800):** H1 "ศูนย์รวมงานวิจัยชั้นเรียน" + บรรทัดรอง + ปุ่มทอง "ลงทะเบียนนำเสนอผลงาน" + ปุ่มรอง "ค้นหางานวิจัย" + กล่องสรุปรอบกิจกรรม: ชื่องาน, ปิดรับสมัครวันที่ (นับถอยหลังเป็นวัน), กิจกรรมถัดไปจาก Timeline
2. **ทางลัด (4 การ์ด):** ลงทะเบียนนำเสนอ, ส่งงานวิจัย (ครู), ดาวน์โหลดเอกสาร, วิดีโอการสอน
3. **Timeline ย่อ:** 3–4 รายการใกล้ปัจจุบัน + ลิงก์ "ดูกำหนดการทั้งหมด"
4. **ข่าวล่าสุด:** 3 การ์ด (รูป, หัวข้อ, วันที่) + ลิงก์ "ดูข่าวทั้งหมด"
5. **Footer**

### ลงทะเบียนนำเสนอ (`register`)
- Stepper 4 ขั้น บนมือถือแสดง "ขั้นที่ 2 จาก 4" แทนแถบเต็ม
- ขั้น 1: ข้อมูลผู้สมัคร / ขั้น 2: เลือก Oral หรือ Poster (radio card) + ชื่อเรื่อง ผู้ร่วมวิจัย สาขา + ลิงก์ดาวน์โหลดแบบฟอร์ม Word ตามประเภท / ขั้น 3: dropzone ตามประเภท / ขั้น 4: สรุปทุกข้อมูล + PDPA + อนุญาตเผยแพร่ + ปุ่มส่ง
- กดย้อนกลับได้โดยไม่เสียข้อมูล
- นอกช่วงเปิดรับ: แสดง empty state พร้อมวันเปิดรับครั้งถัดไป (ถ้ามี)
- หลังส่ง: หน้าสำเร็จ แสดงรหัสงานตัวใหญ่ + ปุ่มคัดลอก + "เราส่งลิงก์ติดตามสถานะไปที่อีเมล ..."
- กด "ถัดไป" ตรวจเฉพาะขั้นนั้น: error ใต้ช่อง + alert สรุปจำนวนด้านบน + focus ช่องแรกที่ผิด
- ขั้น 4 มีปุ่ม "แก้ไข" ต่อส่วนเพื่อกลับไปขั้นนั้น / ประกาศความเป็นส่วนตัวเปิดใน modal (ไม่ออกจากหน้า ข้อมูลไม่หาย)
- ระหว่างส่ง: ปุ่มส่งเป็น loading, ซ่อนปุ่มย้อนกลับ/แก้ไข, dropzone แสดง progress ทีละไฟล์, เตือนก่อนปิดแท็บ
- เมื่อ server สร้างงานแล้ว ข้อมูลผู้สมัครและผลงานแก้ไม่ได้อีก (เปลี่ยนไฟล์ที่ยังไม่สำเร็จได้) ส่งไม่สำเร็จ: alert สีแดง + ปุ่ม "ส่งอีกครั้ง" และปุ่ม "ลองใหม่" บน dropzone ที่ล้มเหลว

### ส่งงานวิจัยครู (`teacher`)
- แท็บ "ส่งงานใหม่" / "งานของฉัน"
- ฟอร์มหน้าเดียว (ไม่ใช้ stepper) ใช้ dropzone ชุดเดียวกับหน้าลงทะเบียน

### ติดตามสถานะ (`track`)
- การ์ดหัว: รหัสงาน ชื่อเรื่อง ป้ายสถานะ
- กล่องหมายเหตุจากผู้ตรวจ (สี warning เมื่อขอแก้ไข)
- Timeline ประวัติสถานะ
- เมื่อขอแก้ไข: dropzone สำหรับไฟล์ฉบับแก้ไข

### Timeline (`timeline`), ข่าว (`news`), ดาวน์โหลดเอกสาร (`documents`), วิดีโอ (`videos`), คลังงานวิจัย (`library`)
- `documents` ใช้โครงจากดีไซน์ Figma เดิม: ช่องค้นหาใน hero + sidebar ตัวกรอง (มือถือ: ปุ่ม "ตัวกรอง" เปิด drawer) + grid document card + pagination
- `library` ใช้โครงเดียวกับ `documents` แต่การ์ดแสดงชื่องาน ผู้วิจัย ประเภท ปี
- `videos`: แท็บหมวดหมู่ (มือถือเลื่อนแนวนอน) + grid video card
- `news`: รายการการ์ดข่าว + หน้ารายละเอียดข่าว (`news?id=`)

### เข้าสู่ระบบ (`login`)
- การ์ดกลางจอ ขั้น 1 ใส่อีเมล / ขั้น 2 ช่องรหัส 6 หลัก (inputmode numeric, autocomplete one-time-code) + ปุ่ม "ส่งรหัสอีกครั้ง" พร้อมนับถอยหลัง

### แอดมิน (`admin`)
- desktop: sidebar เมนู (ภาพรวม, งานที่ส่ง, Timeline, ข่าว, เอกสาร, วิดีโอ, รอบกิจกรรม, ผู้ดูแล) / มือถือ: เมนู dropdown
- ภาพรวม: การ์ดตัวเลข (จำนวนตามประเภทและสถานะ)
- งานที่ส่ง: ตาราง + ตัวกรอง → แผงรายละเอียดด้านขวา (มือถือ: หน้าใหม่)

## 7. ภาพและเนื้อหา

- ใช้ภาพกิจกรรมจริงของโรงเรียน ห้ามใช้ภาพสต็อกหรือภาพที่สร้างด้วย AI ในเวอร์ชันจริง ระหว่างพัฒนาใช้กล่องสีเทาพร้อมคำว่า "ภาพกิจกรรม"
- ชื่อหน่วยงานใช้ "หน่วยส่งเสริมงานวิจัย โรงเรียน มอ.วิทยานุสรณ์" ให้ตรงกันทุกหน้า (ตั้งค่าใน `config.gs` ที่เดียว)
- ข้อมูลติดต่อและโลโก้: placeholder ระหว่างพัฒนา แล้วเปลี่ยนเป็นของจริงก่อน deploy
- วันที่แสดงแบบไทย พ.ศ. เช่น "3 พ.ย. 2569"
