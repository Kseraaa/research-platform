# SPEC: แพลตฟอร์มหน่วยส่งเสริมงานวิจัย โรงเรียน มอ.วิทยานุสรณ์

## 1. ผู้ใช้และสิทธิ์

| Role | ระบุตัวตนอย่างไร | ทำอะไรได้ |
|---|---|---|
| ผู้เยี่ยมชม (ทุกคน) | ไม่ต้องล็อกอิน | ดูหน้าแรก, Timeline, ข่าว, ดาวน์โหลดเอกสาร, คลังวิดีโอ |
| บุคคลภายนอก | ไม่ต้องล็อกอิน ใช้ลิงก์ติดตาม (`track_token`) ที่ส่งไปทางอีเมล | ลงทะเบียน Oral/Poster, ดูสถานะงานตัวเอง, ส่งไฟล์ฉบับแก้ไข |
| ครู | ล็อกอินด้วยรหัส OTP ที่ส่งไปอีเมลโดเมนโรงเรียน | ส่งงานวิจัย, ดูงานของตัวเอง, ดูคลังงานวิจัย |
| ผู้ตรวจ (reviewer) | OTP + มีชื่อในแท็บ `ADMINS` | ดูงานทั้งหมด, เปลี่ยนสถานะ, ใส่หมายเหตุ |
| แอดมิน | OTP + มีชื่อในแท็บ `ADMINS` (role = admin) | ทุกอย่างของ reviewer + จัดการ Timeline, รอบกิจกรรม, วิดีโอ, เอกสาร, ข่าว, รายชื่อแอดมิน |

## 2. ฟีเจอร์

### 2.1 ครูส่งงานวิจัย (`type = teacher`)
- ล็อกอินด้วย OTP ก่อน (ข้อมูลชื่อ/อีเมลดึงจากบัญชี)
- กรอก: ชื่อเรื่อง, ผู้วิจัย (หลายคนได้), กลุ่มสาระ/สาขา, บทคัดย่อสั้น, ปีการศึกษา
- แนบไฟล์: **PDF และ/หรือ Word อย่างน้อย 1 ไฟล์**
- **ต้องเลือก** "อนุญาตให้เผยแพร่ในคลังงานวิจัยของโรงเรียน" ใช่ / ไม่ใช่ (ไม่มีค่า default ต้องเลือกเอง)
- ส่งแล้วได้อีเมลยืนยัน

### 2.2 บุคคลภายนอกลงทะเบียนนำเสนอ
ข้อมูลผู้สมัคร: ชื่อ-นามสกุล, อีเมล, เบอร์โทร, หน่วยงาน/สถานศึกษา, ชื่อเรื่อง, รายชื่อผู้ร่วมวิจัย, ยินยอม PDPA (บังคับ), อนุญาตเผยแพร่ (ใช่/ไม่ใช่)

เลือกรูปแบบการนำเสนอ แล้วฟอร์มแสดงช่องอัปโหลดตามประเภท:

| รูปแบบ | ไฟล์ที่ต้องส่ง (บังคับทุกไฟล์) | `file_kind` |
|---|---|---|
| **Oral** | เปเปอร์วิจัย PDF | `paper_pdf` |
| | เปเปอร์วิจัย Word ตามแบบฟอร์มที่กำหนด | `paper_docx` |
| **Poster** | Abstract PDF | `abstract_pdf` |
| | Abstract Word ตามแบบฟอร์มที่กำหนด | `abstract_docx` |
| | ไฟล์ Poster PDF | `poster_pdf` |

- มีลิงก์ดาวน์โหลด **แบบฟอร์ม Word** ที่กำหนด (ลิงก์ตั้งค่าได้ในแท็บ `EVENTS`)
- รับลงทะเบียนเฉพาะช่วง `open_date` – `close_date` ของรอบกิจกรรมที่เปิดอยู่
- ส่งสำเร็จ → แสดงรหัสงาน (`SUB-2026-0001`) และส่งอีเมลพร้อม **ลิงก์ติดตามสถานะ**

### 2.3 หน้าติดตามสถานะ (`?page=track&t=<token>`)
- แสดงชื่อเรื่อง สถานะปัจจุบัน ประวัติสถานะ หมายเหตุจากผู้ตรวจ
- ถ้าสถานะ = `revision_requested` แสดงฟอร์มอัปโหลดไฟล์ฉบับแก้ไข (เก็บเป็น version ใหม่ ไม่ลบของเดิม)

### 2.4 Timeline กิจกรรม
- แสดงกำหนดการของรอบกิจกรรมปัจจุบัน เรียงตามวันที่
- ไฮไลต์รายการที่กำลังเกิดขึ้น และทำให้รายการที่ผ่านไปแล้วจางลง

### 2.5 คลังงานวิจัย (เฉพาะครู + แอดมิน)
- แสดงงานที่ `allow_publish = TRUE` และสถานะ `accepted` (งานครูที่ `recorded`)
- ค้นหาจากชื่อเรื่อง/ผู้วิจัย, กรองตามปี ประเภท สาขา
- เปิดไฟล์ผ่านลิงก์ Drive ที่แชร์ให้เฉพาะโดเมนโรงเรียน

### 2.6 คลังวิดีโอการสอน
- วิดีโอแยกหมวดหมู่ชัดเจน (แท็บหมวดหมู่ → การ์ดวิดีโอ)
- ฝัง YouTube แบบ Unlisted ด้วย `youtube-nocookie.com`

### 2.7 หน้าแอดมิน
- ตารางงานทั้งหมด กรองตามรอบ ประเภท สถานะ
- เปิดดูรายละเอียดงาน + ไฟล์ทุก version
- เปลี่ยนสถานะ + ใส่หมายเหตุ → บันทึก `STATUS_LOG` และส่งอีเมลอัตโนมัติ
- จัดการ Timeline, รอบกิจกรรม, หมวดหมู่และวิดีโอ, เอกสารดาวน์โหลด, ข่าว
- ปุ่ม Export รายชื่อผู้ลงทะเบียน (ข้อมูลอยู่ใน Sheets อยู่แล้ว ให้ลิงก์ไปแท็บที่กรองไว้)

### 2.8 ศูนย์ดาวน์โหลดเอกสาร (`documents`)
- ทุกคนเปิดดูและดาวน์โหลดได้ ไม่ต้องล็อกอิน
- หมวดหมู่: แบบฟอร์มคำขอทุน, คู่มือผู้ใช้งาน, ตัวอย่างรายงานผลการวิจัย, เทมเพลตและพาวเวอร์พอยต์ (แอดมินเพิ่มหมวดได้)
- ค้นหาจากชื่อเอกสาร/ผู้จัดทำ, กรองตามหมวดและปีการศึกษา, แบ่งหน้าละ 12 รายการ
- การ์ดแสดง: ป้ายชนิดไฟล์, ชื่อเอกสาร, ผู้จัดทำ, ปีการศึกษา, ขนาดไฟล์, ปุ่มดาวน์โหลด
- ชนิดไฟล์ที่แอดมินอัปโหลดได้: PDF, DOCX, PPTX, XLSX
- ไฟล์ในโฟลเดอร์ `_documents` แชร์แบบ "ทุกคนที่มีลิงก์ ดูได้" (เป็นเอกสารสาธารณะ)
- แบบฟอร์ม Word ของ Oral/Poster ที่ฟอร์มลงทะเบียนลิงก์ไป ให้เก็บเป็นเอกสารในหมวดแบบฟอร์มด้วย

### 2.9 ข่าวประชาสัมพันธ์ (`news`)
- หน้าแรกแสดงข่าวล่าสุด 3 ข่าว (ปักหมุดได้)
- หน้ารายการข่าว + หน้ารายละเอียด (`news?id=NEWS-xxxx`)
- แต่ละข่าว: หัวข้อ, วันที่เผยแพร่, รูปปก, เนื้อหา (ข้อความธรรมดาแบ่งย่อหน้า + ลิงก์), สถานะ draft/published
- รูปปกเก็บใน Drive โฟลเดอร์ `_news` แชร์แบบดูได้ แสดงผ่าน URL `https://lh3.googleusercontent.com/d/{fileId}`
- เนื้อหาข่าวต้อง escape ก่อนแสดง (ไม่รับ HTML จากแอดมินโดยตรง)

### 2.10 หน้าตาและการใช้งาน
รายละเอียดสี ฟอนต์ component และโครงแต่ละหน้าอยู่ใน `docs/DESIGN.md`

## 3. สถานะงาน (status)

```
draft ──► submitted ──► under_review ──► accepted
                             │      └──► rejected
                             ▼
                    revision_requested ──► resubmitted ──► under_review
```

| status | ความหมาย (แสดงผลภาษาไทย) | ใครเปลี่ยน | ส่งอีเมล |
|---|---|---|---|
| `draft` | กำลังอัปโหลดไฟล์ (ยังไม่ส่งสมบูรณ์) | ระบบ | ไม่ |
| `submitted` | ส่งงานแล้ว | ระบบ (หลัง finalize) | ใช่ |
| `under_review` | กำลังพิจารณา | ผู้ตรวจ | ใช่ |
| `revision_requested` | ขอให้แก้ไข | ผู้ตรวจ | ใช่ (พร้อมหมายเหตุ) |
| `resubmitted` | ส่งฉบับแก้ไขแล้ว | ผู้สมัคร | ใช่ (แจ้งผู้สมัคร + แอดมิน) |
| `accepted` | ผ่านการพิจารณา | ผู้ตรวจ | ใช่ |
| `rejected` | ไม่ผ่านการพิจารณา | ผู้ตรวจ | ใช่ |
| `recorded` | บันทึกเข้าคลังแล้ว (เฉพาะงานครู) | ผู้ตรวจ | ใช่ |

งาน `draft` ที่ค้างเกิน 24 ชม. ให้ trigger รายวันลบไฟล์และแถวทิ้ง

## 4. ข้อกำหนดไฟล์

- ชนิดที่รับ: PDF (`application/pdf`), Word (`.docx`) เท่านั้น ตรวจทั้งนามสกุลและ MIME type ทั้งฝั่ง client และ server
- ขนาดสูงสุดต่อไฟล์: ค่า `MAX_FILE_MB` ใน config (เริ่มต้น 20 MB)
- ไฟล์ใน Drive **ไม่แชร์สาธารณะ** งานที่เข้าคลังแล้วจึงแชร์แบบ "ทุกคนในโดเมนที่มีลิงก์ ดูได้"
- ตั้งชื่อไฟล์ใหม่ตามรูปแบบ `SUB-2026-0001_paper_pdf_v1.pdf`

## 5. อีเมล (Resend)

ทุกอีเมลเป็นภาษาไทย มีโลโก้/ชื่อหน่วยงาน รหัสงาน ชื่อเรื่อง สถานะ และลิงก์ติดตาม (บุคคลภายนอก) หรือลิงก์เข้าระบบ (ครู)

| template | ส่งเมื่อ |
|---|---|
| `otp` | ขอรหัสเข้าสู่ระบบ |
| `submitted` | ส่งงานสำเร็จ |
| `status_changed` | ผู้ตรวจเปลี่ยนสถานะ (ใส่หมายเหตุถ้ามี) |
| `resubmitted_admin` | แจ้งแอดมินว่ามีฉบับแก้ไขเข้ามา |

ทุกการส่งบันทึกใน `EMAIL_LOG` ถ้าส่งไม่สำเร็จให้บันทึก error ไว้ และไม่ทำให้การบันทึกงานล้มเหลว

## 6. ความเป็นส่วนตัว (PDPA)

- ฟอร์มของบุคคลภายนอกต้องมี checkbox ยินยอมพร้อมลิงก์ประกาศความเป็นส่วนตัว และบันทึก `pdpa_consent_at`
- ไม่แสดงอีเมล/เบอร์โทรของผู้สมัครในคลังงานวิจัย
- แอดมินเท่านั้นที่เห็นข้อมูลติดต่อ

## 7. นอกขอบเขต (ยังไม่ทำในเวอร์ชันแรก)

- ระบบให้คะแนนหลายกรรมการ
- ชำระค่าลงทะเบียน
- ออกเกียรติบัตรอัตโนมัติ (อาจทำในเฟสถัดไปด้วย Google Slides template)
- **ประกาศผลรางวัลงานวิจัย** (มีในดีไซน์ Figma เดิม เลื่อนไปเฟสถัดไป) ระหว่างนี้ใช้ข่าวประชาสัมพันธ์ประกาศผลแทน
  - แนวทางภายหลัง: เพิ่มตาราง `AWARDS` (award_id, event_id, submission_id, award_name, rank, announced_at) และหน้า `awards`
